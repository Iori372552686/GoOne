# 游戏配置规范文档

> **`module/gamedata` 包是运行时配置数据访问中心** — 配置表的注册、本地/远端加载、热更新与便捷查询代码均集中于此包；配置表的 proto 契约、`.conf` 数据、查询代码由 cfgtool 工具链（源码 `tools/cfgtool/`，二进制与 xls 镜像分发到 submodule `g1_common` 的 `common/game_conf/`）从 Excel 源表生成与维护。

## 1. 概述

GoOne 的游戏配置（gamedata）链路如下：

- **配置表 proto 契约**：由 cfgtool 从 `common/game_conf/xls/*.xlsx` 生成，输出到 `common/game_proto/config/`（`enum_config.proto`、`global_config.proto`、`struct_config.proto`、`xlsx_config.proto`）。
- **运行时数据文件**：`.conf`（pb text 格式）文件位于 `common/game_data/`，由 cfgtool 从 xlsx 导出。
- **运行时加载与查询**：在 `module/gamedata` 注册 loader，生成的查询代码位于 `module/gamedata/repository/<sheet>/*.gen.go`，业务代码经它们读取。
- **加载方式**：本地经 `base_cfg.dependencies.game_data_dir` 指定目录读取；远端热更新经 `base_cfg.dependencies.nacos_conf`（未来可扩展 etcd 读取端）。

## 2. 配置表 proto 契约标准

### 2.1 来源与位置

- **不要手写配置表 proto**。proto 由 cfgtool（源码在主仓 `tools/cfgtool/`，二进制分发到 `common/game_conf/`）根据 xlsx 第四行 `@config`/`@struct`/`@enum` 规则自动生成，位于 `common/game_proto/config/`。
- 生成命令（推荐一键脚本，详见 `common/game_conf/readme.md`）：

```bash
# 方式 1：主仓控制台（推荐）
./main.sh xls                          # 全量生成（mode=all）

# 方式 2：在 common/game_conf/ 目录下直接跑分发脚本
cd common/game_conf && ./run_me.sh     # Linux/macOS/Git-Bash
run_me.bat                             # Windows
```

脚本内部调用 `cfgtool`，把产物分发到：
- `.conf`（pb text）→ `common/game_data/`
- 配置表 proto → `common/game_proto/config/`
- Go 查询代码 → `module/gamedata/repository/`

如需直接调二进制（参数详见 `common/game_conf/readme.md`）：

```bash
./common/game_conf/cfgtool -xlsx=./common/game_conf/xls -proto=./gen/proto -text=./gen/text \
  -json=./gen/json -code=./gen/code -mode=all \
  -module=github.com/Iori372552686/GoOne \
  -pb=github.com/Iori372552686/g1_common/protocol
```

- `-proto-src` 可指向 `common/game_proto/core`，使 xlsx 中 `pb.MessageName` 类型引用能解析外部 proto（注意只指 core，不要扫到 config/，否则符号会重定义）。

### 2.2 Message 命名

由 xlsx 表名（`@config|sheet:结构名|...`）决定，生成 message 名为 `{SheetName}Config`，如 `ItemConfig`、`TexasConfig`、`DropItemConfig`。

### 2.3 字段编号

| 范围 | 用途 |
|------|------|
| =1 | 主键字段（xlsx 第四行标记 `key`/`KEY` 的列） |
| =2~ | 业务字段，按 xlsx 列顺序自增 |

> xlsx 第四行可标 `key`/`KEY`（一个或多个列）自动生成主键 Map 索引方法；多列 key 生成复合键索引。不可修改已发布字段编号。

详细语法见 `common/game_conf/readme.md`（与主仓 `tools/cfgtool/README.md` 同步；分隔符规则、类型支持、map/多维数组/外部 proto 引用等）。

## 3. 数据文件格式

运行时数据文件为 **pb text 格式的 `.conf` 文件**，位于 `common/game_data/`：

```
common/game_data/
├── DropItemConfig.conf
├── GlobalConfig.conf
├── ItemConfig.conf
├── MachineConfig.conf
├── MallConfig.conf
├── RechargeConfig.conf
├── TaskConfig.conf
├── TexasConfig.conf
├── TexasTestConfig.conf
└── gamedata.tar
```

> **重要**：服务器侧 `gamedata` 的 parser 硬编码调 `proto.UnmarshalText`，**只认 `.conf`（pb text）格式**。cfgtool 生成的 `.json`/`.bytes` 仅供客户端/工具链消费，不能直接给服务器 `gamedata` 读取（会反序列化失败）。

## 4. 运行时加载与注册（`module/gamedata`）

### 4.1 注册 loader

每个 sheet 在生成代码的 `init()` 中调用 `gamedata.Register(sheet, f)` 注册解析函数：

```go
// module/gamedata/gamedata.go
func Register(sheet string, f func(string) error)   // 重复注册 panic
func InitLocal(dir string) error                     // 读 <dir>/<sheet>.conf
func InitRemote(cli contribconfig.Client) error     // 远端配置中心 + 热更 watcher
func InitNacos(conf net_conf.NacosConf) error       // module/gamedata/remote.go
func StopNet()                                       // 停止热更 goroutine
func SheetFiles() []string                           // 返回 ["ItemConfig.conf", ...]
```

- 初始化语义**严格**：缺失/空/解析失败即返回错误（启动失败）。
- 热更新语义**宽松**：单表失败仅记日志，旧数据保留（每表 `atomic.Value` 原子替换）。

### 4.2 加载入口（服务装配时）

各服务在 `src/<svc>/app.go` 的 `NewApp()` 中，通过 `bussvc.WithConfLoader(hooks...)` 注入加载逻辑：

```go
// 本地 gamedata（开发）
app := bussvc.MustNew("mainsvr", router.ReadyCheck,
    bussvc.WithConfLoader(gamedataHook))   // gamedataHook 调 gamedata.InitLocal(gameDataDir)

// 远端 Nacos 热更（生产）
// gamedataHook 调 gamedata.InitNacos(nacosConf)
```

`gameDataDir` / `nacosConf` 来自 `conf.Unmarshal("base_cfg.dependencies", &deps)`。

## 5. 数据查询（生成 repository）

查询代码由 cfgtool（`-code` 参数）生成到 `module/gamedata/repository/<sheet>/`，命名模式 `<Sheet>Data.gen.go`：

```
module/gamedata/repository/
├── drop_item_config/DropItemConfigData.gen.go
├── global_config/GlobalData.gen.go
├── item_config/ItemData.gen.go
├── machine_config/MachineData.gen.go
├── mall_config/MallData.gen.go
├── recharge_config/RechargeData.gen.go
├── task_config/TaskData.gen.go
├── texas_config/TexasData.gen.go
└── texas_test_config/TexasTestData.gen.go
```

> ⚠️ `repository/**/*.gen.go` 是**生成代码，禁止手改**（见 `AGENTS.md` "Generated Code Boundaries"）。改表后重新跑 `./main.sh xls`。

### 统一查询 API

```go
item := item_config.GetByList(1001)      // Map 索引查找（由 xlsx key 标记生成）
all  := item_config.GetAll()             // 获取全部
cnt  := item_config.Count()              // 记录数
rare := item_config.Filter(func(c *pb.ItemConfig) bool { return c.Quality >= 4 })
first := item_config.Find(func(c *pb.ItemConfig) bool { return c.Name == "金币" })
item_config.Range(func(c *pb.ItemConfig) bool { /* 遍历 */ return true })
```

## 6. 数据流

```
common/game_conf/xls/*.xlsx
        │  cfgtool (源码 tools/cfgtool/，二进制 common/game_conf/cfgtool)
        ▼
common/game_proto/config/*.proto (契约)
module/gamedata/repository/**/*.gen.go (查询代码)
common/game_data/*.conf (pb text 运行时数据)
        │  本地: gamedata.InitLocal(game_data_dir) 直接读 common/game_data/
        │  远端: cfgtool -upload 上传到配置中心
        ▼
服务启动: gamedata.InitLocal(dir) / InitNacos(conf)
        ▼
业务代码: repository/<sheet> 查询 (GetById/Filter/Range...)
```

### 6.1 正向导出规则（强制）

- **xlsx 是配置表的唯一数据源**。`common/game_conf/xls/*.xlsx` 为策划配置入口，`common/game_data/*.conf` 仅作为运行时产物。
- **禁止直接修改 `common/game_data/*.conf`**。任何配置增删改都必须回到 xlsx 源表，再经 `./main.sh xls`（或 `common/game_conf/run_me.sh`）正向导出。
- 若发现 `.conf` 与 xlsx 不一致，应以 xlsx 为准重新导出。

### 6.2 上传到配置中心（生产热更）

cfgtool（源码 `tools/cfgtool/`）支持把生成的产物直接发布到配置中心（复用 `lib/contrib/config` 地址解析）：

```bash
# 上传 .conf 到 etcd 开发环境（需 -tags config_etcd 编译 cfgtool）
./common/game_conf/cfgtool -xlsx=./common/game_conf/xls -text=./gen/text -proto=./gen/proto \
  -upload="etcd://host:2379?path=/goone/config/dev" -uptype=conf

# 上传到 nacos（文本产物）
./common/game_conf/cfgtool -xlsx=./common/game_conf/xls -json=./gen/json -text=./gen/text \
  -upload="nacos://host:8848?group=GOONE_CONFIG&namespace_id=public" -uptype=json,conf
```

> **读取端契约**：服务器 `gamedata` 当前生产读取端**只接了 Nacos**（`gamedata.InitNacos`）。etcd 读取路径需补一处路径前缀剥离适配（详见 `common/game_conf/readme.md` "读取端契约"章节）。详细上传/校验流程见该 readme。

## 7. 新增配置表流程

1. 在 `common/game_conf/xls/` 新增/修改 xlsx 表，按 readme 规范填写表头（第一行中文名、第二行字段名、第三行类型、第四行 `all`/`client`/`server`/`key`）
2. 运行 `./main.sh xls`（或 `cd common/game_conf && ./run_me.sh`）生成 proto、`.conf`、查询代码
3. 生成的 proto 自动落到 `common/game_proto/config/`，查询代码自动落到 `module/gamedata/repository/<sheet>/`，`.conf` 自动落到 `common/game_data/`
4. 生产环境把 `common/game_data/` 下的 `.conf` 上传配置中心（见 6.2）
5. 业务代码引用 `repository/<sheet>` 的查询 API
6. 验证：`go build ./...` 编译通过，`.conf` 文件生成正确
