# 玩家服务数据库协议规范文档

> **GoOne 的玩家（role）数据持久化与 Seed 风格的"整文档 KV + dbrouter"模型不同**：玩家主数据由 `mainsvr` 直连 Redis 以 hash 形式落盘（按模块增量写），只有少量字段（如 name）经 `mysqlsvr` 落 MySQL。GoOne **没有** dbrouter / 分库分表 / StrategyHash/Mod/Range 概念。

## 1. 概述

`mainsvr` 是有状态服务，玩家状态经 `globals.RoleMgr` 管理。持久化分两层：

- **Redis（主存储 / 缓存）**：`mainsvr` 直连 `lib/db/redis` 多实例，玩家完整数据以 **Redis hash** 形式按模块增量读写（见 `src/mainsvr/role/persist_hash.go`）。
- **MySQL（少量关键字段）**：经 `mysqlsvr` 服务落 `role_info` 表（当前仅 uid + name），通过 ssrpc 异步调用。

玩家数据的存储 KV 抽象 proto 位于 `common/game_proto/storage/`（`db.proto`、`dbsvr.proto`），但当前 mysqlsvr 业务侧主要走 ORM + 裸 SQL。

---

## 2. 核心约定

| 约定 | 规则 |
|------|------|
| 主存储 | Redis（`lib/db/redis`，多实例按 `instID` 区分） |
| 关键字段持久化 | MySQL（`mysqlsvr` 服务的 `role_info` 表） |
| 分片层级 | **服务实例级**（`ServerInstanceMgr` 按 `ServerType_MainSvr` + `SvrRouterRule_Hash_UID` 路由到 mainsvr 实例），**非数据库级** |
| 分库分表 | ❌ GoOne 无 dbrouter / 应用层分片概念 |
| Redis 高可用 | 生产环境强制 Sentinel / Cluster（由 `lib/db/redis` 配置） |
| 配置不可变 | 启动配置经 `module/conf` 加载后不可变；唯一热更是 gamedata |

## 3. 数据存储结构

### 3.1 Redis hash 落盘（mainsvr 直连）

玩家数据按模块组织成 Redis hash，`src/mainsvr/role/role.go` 的关键方法：

| 方法 | 说明 |
|------|------|
| `Role.SaveToDB(trans)` | 按模块增量写 Redis hash（调 `saveRoleHash`） |
| `Role.SaveToMysql(trans)` | 经 ssrpc 调 `mysqlsvr.UpdateRoleInfo` 落 `role_info` 表（当前仅 name） |
| `Role.SaveToDBSync()` | 同步写 Redis，不依赖事务上下文（用于优雅停机全量落盘） |

落盘格式实现见 `src/mainsvr/role/persist_hash.go`（每个业务模块对应 hash 的一个 field，序列化为 protobuf bytes）。

### 3.2 Redis 访问 API（`lib/db/redis`）

```go
// 多实例，按 instID 获取 client
cli := rds.RedisMgr.GetClient(instID)
cli.SetBytes(key, val)
cli.SetBytesEx(key, val, ttl)
v, _ := cli.GetBytes(key)
cli.DelKey(key)
cli.IncrKey(key)
// zset / hash 等
```

Redis 实例经 `base_cfg.dependencies.db_instances`（`[]redis.Config`）配置，`InitAndRun(dbIns)` 启动。

### 3.3 MySQL `role_info` 表（mysqlsvr）

当前 `role_info` 表仅两列，用裸 SQL 访问（见 `src/mysqlsvr/service/mysql_ssrpc.go`）：

```sql
INSERT INTO role_info VALUES (?, ?)        -- uid, name
UPDATE role_info SET name = ? WHERE uid = ?
SELECT uid FROM role_info
```

## 4. 路由规则（服务实例级，非 DB 级）

GoOne 的"路由"指的是**消息/请求路由到哪个服务实例**，由 `lib/service/svrinstmgr` + `module/misc/ServerRouteRules` 决定，而非数据库分片。

| 服务 | 路由规则（`SvrRouterRule_*`） | 路由 Key |
|------|------|------|
| mainsvr | `Hash_UID` | 玩家 UID 取模选定实例 |
| mysqlsvr | `Hash_RouterID` | RouterID 取模 |
| infosvr | `Hash_UID` | 玩家 UID 取模 |

```go
// lib/service/svrinstmgr/svr_inst_mgr.go 路由常量
SvrRouterRule_Random              // 随机
SvrRouterRule_Hash_UID            // UID 取模
SvrRouterRule_Hash_ZoneID         // ZoneID 取模
SvrRouterRule_Hash_RouterID       // RouterID 取模
SvrRouterRule_IoCache_RouterID    // RouterID 一致性哈希
SvrRouterRule_Master              // 主备，永远取第一个
SvrRouterRule_ConsistentHash_UID  // UID 一致性哈希
SvrRouterRule_ConsistentHash_ZoneID
SvrRouterRule_ConsistentHash_RouterID
```

> 业务代码不需要手动"路由到分库"。读写玩家数据由 mainsvr 实例本地直连 Redis 完成；跨服务经 ssrpc client 调用，router 自动按规则选定目标实例。

## 5. 数据生命周期

```
玩家创建 → mainsvr RoleMgr 创建 Role（内存）→ 初始化 Redis hash
登录    → RoleMgr 加载 Role（从 Redis hash 反序列化各模块）
在线    → 内存操作；role_tick（每分钟）定时落盘
下线    → SaveToDB（增量 Redis hash）+ SaveToMysql（role_info）
优雅停机 → roleFlushComponent（Drainer）全量 SaveToDBSync
```

`mainsvr` 的 `NewApp()` 装配关键组件：
- `roleTick`（`scheduler.New("role_tick", time.Minute, ...)`）：每分钟 `RoleMgr.Tick()` 落盘
- `roleFlushComponent`（实现 `Drainer`）：停机时全量落盘角色
- `selfLogout`：注入 `role.SelfLogoutSender`（心跳淘汰经事务串行，避免 handler 与后台 goroutine 共享可变对象）

## 6. 通用 KV 抽象（`common/game_proto/storage/`）

面向 dbsvr 的统一 KV 接口定义在 `storage/dbsvr.proto`，提供：

| 方法 | 说明 |
|------|------|
| `DBUidGet` / `DBUidSet` | 按 UID 的 KV 读写 |
| `DBCommGet` / `DBCommSet` / `DBCommDel` / `DBCommIncr` | 通用 KV |
| `DBCommZsetSet` / `DBCommZsetGet` / `DBCommFindRank` / `DBCommZRevRange` | 有序集合（排行榜） |
| `DBCommExpire` / `DBCommSetExNx` | 过期 / NX |

> 注意：这套抽象是面向独立的 dbsvr 服务的，**当前 mysqlsvr 未使用这套接口**（mysqlsvr 走 ORM + 裸 SQL）。它为未来统一的 DB 服务预留。

## 7. 新增玩家数据模块流程

1. 在 `common/game_proto/core/` 定义模块的 DB 结构体 proto（如 `role.proto` 扩展）
2. 运行 `go run ./tools/cmd/genproto` 生成 `.pb.go`
3. 在 `src/mainsvr/role/` 实现模块的加载/保存（接入 `persist_hash.go` 的 hash field 编排）
4. 如需落 MySQL，在 `mysqlsvr` 加表（ORM struct 注册到 `src/mysqlsvr/manager/table_mgr.go` 的 `tables` 列表）+ 实现 ssrpc handler
5. 业务 handler 经 `globals.RoleMgr` 操作 Role，落盘走 `SaveToDB`/`SaveToMysql`
6. 验证：`go build ./...`，测试完整数据流（`lib/internal/itest` 或 `tools/tester`）
