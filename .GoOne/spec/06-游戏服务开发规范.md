# 游戏服务开发规范

> **`src/<svc>svr/` 是服务实现的标准路径，`cmd/<svc>/main.go` 是程序入口。** 每个服务遵循一致的 `NewApp() *runtime.App` 装配模式，组件经 `runtime.Component` 接口管理生命周期。

---

## 1. 服务结构

### 1.1 标准模式（入口 + 装配分离）

**程序入口** `cmd/<svc>/main.go`（所有服务一字一样，只换包名）：

```go
package main

func main() {
    flag.Parse()
    defer logger.Flush()
    if err := connsvr.NewApp().Run(context.Background()); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }
}
```

配置路径经 `-svr_conf` flag 注入（`module/conf` 解析）。

**装配逻辑** `src/<svc>/app.go`（包名 `connsvr`/`mainsvr`/...，`web_svr` 目录的包名是 `websvr`）：

```go
func NewApp() *runtime.App {
    app := bussvc.MustNew("infosvr", router.ReadyCheck, bussvc.WithConfLoader())
    transMgr := &bussvc.TransMgrComponent{Mgr: globals.TransMgr}
    registerHandlers := ssrpc.NewRegistryComponent(
        "ssrpc_registry",
        func(r *ssrpc.Registry) error {
            srv := infosvrv1.NewInfoServiceSServer(&service.InfoServiceImpl{}, ssrpc.DefaultMWOptions{})
            return infosvrv1.RegisterInfoServiceToRegistry(r, srv)
        },
        ssrpc.WithTransactionManager(globals.TransMgr),
    )
    routerComp := bussvc.NewRouterComponent(app, globals.TransMgr, rabbitmq.NewRegistry())
    app.MustRegister(redisDeps, registerHandlers, transMgr, routerComp)
    return app
}
```

### 1.2 装配关键约定（AGENTS.md "Runtime Model"）

- 服务名只在 `bussvc.MustNew` 出现一次；标准组件（datetime/logger/admin/tracing）由 `MustNew` 集中注册（Start 顺序：datetime → logger → admin → tracing）。
- `bussvc.WithConfLoader(hooks...)`：标准 LoadConfig 闭包（`conf.Load` → `conf.RunValidators(svc)` → 执行 hooks，如 gamedata 加载）。
- `app.MustRegister(...)`：注册顺序即 Start 顺序；Quiesce/Drain/Stop 按注册**逆序**。
- bus 服务传 `router.ReadyCheck`；`websvr` 传 `nil`（非 bus 服务）。
- DriverRegistry 通常只注册 rabbitmq（`rabbitmq.NewRegistry()`）。

### 1.3 组件接口（`lib/service/runtime/component.go`）

```go
type Component interface {
    Name() string
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
}
// 可选扩展
type Quiescer interface{ Quiesce(ctx) error }       // 停止接收新请求
type Drainer interface{ Drain(ctx) error }            // 排空在途请求
type RuntimeErrorSource interface{ RuntimeErrors() <-chan error }
```

状态机：`Starting → Ready → (Allocated) → Draining → Stopping → Stopped`，非法转换或不可恢复错误进 `Failed`。

### 1.4 标准组件便捷构造（`lib/service/runtime/bussvc/stdcomp.go`）

- `NewLoggerComponent(app)`、`NewAdminComponent(app, readyCheck)`、`NewTracingComponent(app)`、`NewDateTimeComponent()`
- `NewRouterComponent(app, transMgr, drivers, onRecvSSPacket...)`
- `FuncComponent`：把任意 `OnStart`/`OnStop` 闭包适配为 Component（用于装配 DB 依赖、gamedata 加载等）

## 3. 事务与并发模型

所有 bus 服务用 **sharded transaction**（`lib/service/transaction`）：

- 响应按 `DstTransID` 路由，请求按 `RouterID`/`Uid` 串行键分片。
- Shard count 固定 `transaction.DefaultShardCount()`（基于 `GOMAXPROCS`，上限 32），不可外部调参。
- 同键队列 backpressure 默认 `DefaultMaxPendingPerKey = 100`；`roomcentersvr` 显式覆盖为 200。
- **handler 必须保持 key-local**（同一 RouterID/Uid 串行），禁止依赖全局单线程排序。
- handler 内禁止与后台 goroutine 共享可变对象（参考 mainsvr 的 `SelfLogoutSender` 模式：经事务串行化心跳淘汰）。

## 4. SSRPC 注册规范

推荐路径（IDL 驱动，CI 强制）：

```go
// src/<svc>/app.go
registerHandlers := ssrpc.NewRegistryComponent(
    "ssrpc_registry",
    func(r *ssrpc.Registry) error {
        srv := <svc>v1.New<Svc>SServer(&service.Impl{}, ssrpc.DefaultMWOptions{})
        return <svc>v1.Register<Svc>ToRegistry(r, srv)
    },
    ssrpc.WithTransactionManager(globals.TransMgr),
)
```

- 生成代码在 `api/gen/game/<svc>/v1/<svc>service.goone_ssrpc.gen.go`。
- **禁止**生产代码调用 `RegisterXxxToDispatcher` / `RegisterXxxToTransactionMgr` / `TransMgr.RegisterCmd`（CI 静态门禁，仅生成代码内部可用）。
- 跨服务调用经 ssrpc client：`<svc>v1.New<Svc>Client().Method(trans, &req)`。

## 5. 配置访问规范

唯一入口 `module/conf`，禁止新 package-level config 全局：

```go
// key 式访问
port := conf.Get("connsvr.runtime.listen_port").Int()
logDir := conf.Get("connsvr.debug.log_dir").String()

// struct 反序列化（带 yaml tag）
var deps gconf.BaseDependenciesConfig
conf.Unmarshal("base_cfg.dependencies", &deps)
```

- 配置 struct 类型在 `module/gconf/config.go`（仅类型定义，无全局状态）。
- 校验在 `module/conf/registry.go` 按服务注册，启动时 `conf.RunValidators("<svc>")` 执行。
- admin 端口 fallback 用命名常量（connsvr→8101、mainsvr→8102、infosvr→8103、mysqlsvr→8104、roomcentersvr→8111、websvr→8112）。

## 6. 测试规范

### 6.1 单元测试

- 位于被测包同级目录，`*_test.go` / `*_bench_test.go`。
- **不依赖外部中间件**；性能改动必须附 benchmark（`docs/benchmarks/baseline.md` 流程）。

```bash
go test -count=1 -timeout 600s ./...
go test -race ./src/mainsvr/...
```

### 6.2 集成测试

- 经 `lib/internal/itest.Require`，`GOONE_INTEGRATION=1` 时中间件不可达必须 `t.Fatal`（禁静默跳过）。
- CI 的 `integration` job 起真实 mysql/redis/zk/rabbitmq。

### 6.3 客户端联调 / 压测

- 独立客户端框架 `tools/tester/`（CSPacketHeader + protobuf 线协议）：

```bash
# regression 模式
go run ./tools/tester/cmd/tester -config ./tools/tester/tester.toml
# stress 模式
go run ./tools/tester/cmd/stress -config ./tools/tester/stress.toml
```

- 新业务测试组件放 `tools/tester/app/component/<name>/`，`component.Register(...)` 注册，实现 `TesterComponent`；压测加 `StressRunner`。

### 6.4 脚手架（新服务）

```bash
go run tools/cmd/scaffold -name mysvr    # 生成 src/mysvrsvr/（结构同 infosvr）
```

## 7. 代码风格（`docs/STYLE.md` 硬性要求）

要点（详见 STYLE.md）：

- **命名**：包名全小写单词；服务目录 `<name>svr` 连写（存量 `web_svr` 保留但新服务不得用下划线）；文件名 snake_case；新接口用 `er` 后缀，禁 `I` 前缀（`IBus`/`IContext` 为存量兼容）。
- **注释统一中文**；导出符号注释以符号名开头；生成代码保持原样。
- **错误处理**：统一 `lib/api/gerr`（或 ssrpc 的 `ssrpc.E`/`Wrap`）；禁裸 `errors.New` 穿越 RPC；禁 `rsp.Ret.Code = ERR_X` 后 `return rsp, nil`。
- **并发**：串行化优先复用 TransactionMgr serial key；channel 入队必须有界；select 禁用 `time.After`；goroutine 内用 `safego.Go`。
- **热路径**：Debug 日志加 `logger.DebugEnabled()` 前置；禁每消息 `make`/goroutine。
- **生命周期（P0）**：每个资源归属唯一 Component；每个 goroutine 能被 Stop/Drain 取消并 join；`Start` 返回 nil 即可用，失败自行清理；`Stop` 幂等。
