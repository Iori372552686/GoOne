# 游戏微服务数据库协议规范文档

> **GoOne 的服务数据持久化以服务为域独立组织**：每个服务经自己的 `app.go` 装配所需的 DB 依赖（Redis/ORM），通过 `base_cfg.dependencies` 配置实例。GoOne **没有** dbrouter / 分库分表 / StrategyHash/Mod/Range 概念，分片只在服务实例层（`SvrRouterRule_*`）。

## 1. 概述

各服务的数据域：

| 服务 | 数据域 | 存储 | 访问方式 |
|------|--------|------|---------|
| connsvr | 客户端会话（无持久化） | Redis（session/sign/rest 配置） | `lib/web/http_sign`、`lib/web/rest_api` |
| mainsvr | 玩家主数据 | Redis hash（主） + MySQL `role_info`（经 mysqlsvr） | 见 [03-玩家服务数据库协议规范文档.md](./03-玩家服务数据库协议规范文档.md) |
| infosvr | 玩家 BriefInfo / IconDesc 缓存 | Redis | `lib/db/redis` |
| mysqlsvr | 角色名、Texas 房间/玩家/对局明细 | MySQL（xorm ORM + 裸 SQL） | `lib/db/xorm` |
| roomcentersvr | 房间列表 / 快照 | Redis（主） + MySQL（经 mysqlsvr） | `lib/db/redis` + ssrpc |
| web_svr | 对外接口（无自有持久化） | Redis（sign/rest 配置） | Gin HTTP / gRPC |

---

## 2. 核心约定

| 约定 | 规则 |
|------|------|
| 关系型数据库 | MySQL 8.x（`lib/db/xorm`，主从 `EngineGroup`） |
| KV / 缓存 | Redis（`lib/db/redis`，多实例按 `instID`） |
| 分片层级 | **服务实例级**（`SvrRouterRule_*`），非数据库级 |
| 分库分表 | ❌ GoOne 无此概念 |
| Redis 高可用 | 生产环境强制 Sentinel / Cluster |
| 异步写库 | `lib/service/async`（如 mysqlsvr 用 `async.NewAsyncPool(15)`） |

---

## 3. 服务实例路由规则（`module/misc/ServerRouteRules`）

| ServerType | 路由规则 | 路由 Key |
|---|---|---|
| ConnSvr(1) | 不受限（网关） | - |
| MainSvr(2) | `Hash_UID` | 玩家 UID |
| InfoSvr(3) | `Hash_UID` | 玩家 UID |
| MysqlSvr(4) | `Hash_RouterID` | RouterID |
| RoomCenterSvr(11) | `Hash_RouterID` | RouterID |
| WebSvr(12) | `Random` | - |
| TexasGameSvr(0x50) | `Hash_RouterID` | RouterID |

> 业务代码不手动路由。跨服务调用经 ssrpc client，router 按 `ServerRouteRules` 自动选定目标实例。

## 4. MySQL 访问（`lib/db/xorm`）

### 4.1 ORM 配置

实例经 `base_cfg.dependencies.orm_instances`（`[]orm.Config`）配置，`OrmMgr.InitAndRun` 启动。`orm.Config` 支持主 + 多从 DSN：

```go
type Config struct {
    IndexName string
    Master    DSN   // 主库
    Slaves    []DSN // 从库
    // ...
}
```

### 4.2 mysqlsvr 表清单

`src/mysqlsvr/manager/table_mgr.go` 同步的 ORM 表：

```go
var tables = []interface{}{
    new(g1_protocol.MysqlTexasRoomInfo),
    new(g1_protocol.MysqlTexasPlayerInfo),
    new(g1_protocol.MysqlTexasGameInfo),
}
```

另有 `role_info` 表（uid + name），用裸 SQL 访问（不走 ORM struct）。

### 4.3 异步写库

mysqlsvr 用 `async.NewAsyncPool(15)` 异步落库，按 `id % 15` 分发到 15 个 worker，避免阻塞事务。

## 5. Redis 访问（`lib/db/redis`）

### 5.1 多实例

Redis 实例经 `base_cfg.dependencies.db_instances`（`[]redis.Config`）配置。每个实例按 `instID` 标识：

```go
cli := rds.RedisMgr.GetClient(instID)
cli.SetBytes / SetBytesEx / GetBytes / MGetBytes / DelKey
cli.ZsetSet / ZsetRange
cli.IncrKey / IncrByKey
```

### 5.2 各服务 Redis 用途

| 服务 | Redis 用途 |
|------|-----------|
| mainsvr | 玩家数据 hash 落盘、IDGen（`lib/util/idgen`，sonyflake） |
| infosvr | BriefInfo / IconDesc 缓存 |
| roomcentersvr | 房间列表快照（启动从 Redis 恢复，定时持久化） |
| web_svr | sign/rest 配置 |
| connsvr | sign/rest 配置 |

---

## 6. 数据保存策略

| 服务 | 写入方式 | 触发时机 |
|------|---------|---------|
| mainsvr | Redis hash 增量（`SaveToDB`） + mysqlsvr role_info（`SaveToMysql`） | role_tick 每分钟 / 下线 / 停机 |
| mysqlsvr | MySQL ORM `Insert/Update` + 裸 SQL（role_info） | ssrpc handler 内异步写 |
| roomcentersvr | Redis 快照 + mysqlsvr（Texas 三表） | roomPersist 每 10s / 停机 |
| infosvr | Redis 缓存 | `SetBriefInfo` 等 ssrpc handler |

## 7. Proto 组织

### 7.1 目录

```
common/game_proto/
├── core/
│   ├── database.proto            # 数据库相关共享消息
│   ├── role.proto                # 角色结构（含 MysqlTexas* 等 ORM 表 struct）
│   └── ...
├── service/
│   ├── mysqlservice.proto        # MysqlService（UpdateRoleInfo/SearchRole/QueryRoomInfo...）
│   └── mysqlsvr.proto            # mysqlsvr 底层消息
└── storage/
    ├── db.proto                  # 通用 DB 消息
    └── dbsvr.proto               # dbsvr KV 抽象（DBUidGet/Set、DBComm* 等）
```

### 7.2 代码生成

```bash
# 主仓 proto 生成
go run ./tools/cmd/genproto
./main.sh check-genproto           # 校验 api/gen 无 diff

# 子模块 proto 生成
./main.sh proto game
./main.sh check-genproto --full    # 连 common/protocol 一起校验
```

生成的 `.pb.go` 在 `common/protocol/`，ssrpc wrapper 在 `api/gen/game/<svc>/v1/`。

## 8. 新增服务/数据表流程

1. 在 `common/game_proto/core/` 定义表 struct proto（ORM 表用 message，字段对应列）
2. 在对应 `service/*.proto` 定义 ssrpc rpc method（配 `cmd`/`cmd_name` option）
3. 运行 `go run ./tools/cmd/genproto` + `./main.sh check-genproto`
4. 在目标服务 `src/<svc>svr/` 实现 ssrpc handler（`New<Svc>SServer` + `Register<Svc>ToRegistry`）
5. 如需 ORM，把表 struct 注册到 `table_mgr.go` 的 `tables` 列表（mysqlsvr）；其它服务按需装配 `OrmMgr`
6. 配置实例：`base_cfg.dependencies.orm_instances`（MySQL）/ `db_instances`（Redis）
7. 验证：`go build ./...`，集成测试经 `lib/internal/itest`（`GOONE_INTEGRATION=1`）
