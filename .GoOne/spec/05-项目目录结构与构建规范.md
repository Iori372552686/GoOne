# 项目目录结构与构建规范

> **GoOne 是单 Go module（`github.com/Iori372552686/GoOne`），无 go.work workspace。** 共享公共子模块 `g1_common`（`common/`）通过本地 `replace` 引入。所有构建、运行、代码生成操作均以项目根目录为上下文。

---

## 1. 模块与子模块

| 模块 | 路径 | 说明 |
|------|------|------|
| GoOne 主模块 | `go.mod` (`github.com/Iori372552686/GoOne`) | 主体代码，单 module |
| g1_common（子模块） | `common/` | 共享协议定义 + 配置工具链 + 敏感词，`replace github.com/Iori372552686/g1_common => ./common` |

> 不存在 seed-engine/seed-app/seed-game/seed-data/seed-tester 等多模块 workspace。框架核心库在主模块的 `lib/` 下。

---

## 3. 构建规范

### 3.1 推荐入口 `main.sh`

```bash
./main.sh help                # 查看所有子命令
./main.sh doctor              # 自检工具/脚本/inventory
./main.sh build [target]      # 构建（委托 build.sh）
./main.sh build list          # 列出可用目标
./main.sh check-genproto      # 校验 api/gen 无 diff
./main.sh check-genproto --full  # 连 common/protocol 一起校验
./main.sh proto [game|full]   # proto 生成
```

> Windows 上优先用 `build.ps1`；`main.sh` 建议在 WSL 或 Git-Bash 下运行。

### 3.2 构建目标（`build.sh` / `build.ps1`）

输出到 `build/` 目录：

| 目标别名 | 输出二进制 | 源码路径 |
|---------|-----------|---------|
| `conn` / `connsvr` | `connsvr` | `cmd/connsvr` |
| `main` / `mainsvr` | `mainsvr` | `cmd/mainsvr` |
| `info` / `infosvr` | `infosvr` | `cmd/infosvr` |
| `mysql` / `mysqlsvr` | `mysqlsvr` | `cmd/mysqlsvr` |
| `roomcenter` / `roomcentersvr` | `roomcentersvr` | `cmd/roomcentersvr` |
| `web` / `websvr` / `web_svr` | `websvr`（注意无下划线） | `cmd/web_svr` |
| `tester` | `tester` | `tools/tester/cmd/tester` |
| `stress` | `stress` | `tools/tester/cmd/stress` |

```bash
# 构建全部活跃服务 + tester
./build.sh conn main info mysql roomcenter web tester stress

# Windows
.\build.ps1 conn main info mysql roomcenter web tester stress
```

### 3.3 build tag

- 用 etcd 作为注册中心时需带 build tag：
  ```bash
  GO_BUILD_TAGS=registry_etcd ./main.sh build conn
  # Windows PowerShell
  $env:GO_BUILD_TAGS='registry_etcd'; .\build.ps1 conn
  ```

### 3.4 手动构建

```bash
go build -o build/connsvr  ./cmd/connsvr
go build -o build/mainsvr  ./cmd/mainsvr
go build -o build/tester   ./tools/tester/cmd/tester
```

## 4. 运行规范

### 4.1 配置入口

- 统一入口 `module/conf`，经 `-svr_conf` flag 指定配置文件（yaml/toml/json 按扩展名解析）。
- 默认路径 `./etc/config/server_conf.yaml`；部署环境默认 `/data/GoOne/commconf/server_conf.yaml`（可 `SERVER_CONF` 覆盖）。
- 示例配置：`etc/config/server_conf_ide.yaml`（分组写法：`base_cfg` + 各服务段）。

### 4.2 配置分组约定

```
base_cfg:
  runtime:        { register_addr, bus_mq_addr, admin_server, tracing }
  dependencies:   { game_data_dir, sensitive_words_file, db_instances, orm_instances, http_sign, rest_api_config, nacos_conf }
  debug:          { pprof }
<svc>:
  identity:       { self_bus_id }
  debug:          { log_dir, log_level }
  runtime/capacity: （各服务特有）
```

- `register_addr` 支持 `zk://`、`etcd://`、`consul://`、`nacos://`、`k8s://` scheme。
- `bus_mq_addr` 默认 `amqp://...`（RabbitMQ）。
- BusId 格式：点分 4 段 `worldID.zoneID.funcID.insID`（funcID 即 ServerType），例 `2.1.1.251`(connsvr)、`2.1.2.251`(mainsvr)。

### 4.3 本地中间件（`etc/env/env_docker.yaml`）

docker compose 拉起：MySQL 8.4.3（3306）、Redis 7.4.0（6379）、Zookeeper（2181）、RabbitMQ 3.13.6（5672 + 15672 管理）。凭据经同目录 `.env`（git 忽略，模板 `.env.example`）。

```bash
./main.sh docker up --env dev      # 启动本地中间件
./main.sh docker status
```

## 5. Proto 与配置表代码生成

### 5.1 通讯协议 proto（ssrpc IDL）

```bash
# 主仓 proto 生成 + 校验
go run ./tools/cmd/genproto
./main.sh check-genproto

# 子模块（g1_common）proto 生成
./main.sh proto game

# 全量（主仓 + 子模块）
./main.sh proto full
./main.sh check-genproto --full
```

- 改 proto 后必须跑生成 + 校验，禁止手改 `api/gen/**` 与 `common/protocol/*.pb.go`。

### 5.2 CMD 镜像生成

```bash
# 从 common/protocol.CMD 镜像生成 api/proto/goone/cmd/v1/cmd.proto
go run ./tools/cmd/gencmdproto
```

### 5.3 配置表（gamedata）

见 [01-游戏配置规范文档.md](./01-游戏配置规范文档.md)。由 cfgtool（源码 `tools/cfgtool/`，二进制 `common/game_conf/cfgtool`）从 xlsx 生成 proto/conf/查询代码；一键入口 `./main.sh xls` 或 `common/game_conf/run_me.sh`。

## 6. 部署规范（Ansible）

部署资产在 `deploy/`：

```
deploy/
├── deploy.sh                  # CLI 封装（env list / role list / run）
├── playbook_dev/
│   ├── dev1.yml / dev2.yml / dev_local.yml
│   └── <env>_vars
├── roles/<svc>/               # connsvr/mainsvr/infosvr/mysqlsvr/roomcentersvr/websvr/commconf/gamedata 等
├── hosts/host_<env>.txt
├── inithost/                  # OS 初始化
└── scripts/server.sh          # 目标机单服务 start/stop/restart/check/reload
```

```bash
./main.sh deploy --env dev1 --action push --roles connsvr,mainsvr
./main.sh deploy --env dev1 --action start
./main.sh env list
./main.sh role list
```

默认配置路径 `/data/GoOne/commconf/server_conf.yaml`。

## 7. 约束

- **单 module**：不要引入 `go.work` 或新的 `replace`（除现有 `g1_common`）。
- **禁止手改生成代码**：`api/gen/**`、`common/protocol/*.pb.go`、`module/gamedata/repository/**/*.gen.go`。
- **启动配置不可变**：`module/conf` 加载后发布原子快照；唯一热更是 gamedata。
- **bus 服务 driver 显式注册**：通常只注册 rabbitmq（`rabbitmq.NewRegistry()`），禁止 blank-import `bus/driver/all`（CI 门禁）。
- **SSRPC 注册走生成代码**：`RegisterXxxToRegistry`，禁止生产代码用 `RegisterXxxToDispatcher`/`RegisterXxxToTransactionMgr`/`TransMgr.RegisterCmd`（CI 门禁）。
