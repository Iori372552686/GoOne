# 系统调试

## 铁律

**没有根本原因调查，绝不修复。**

修复症状会造成打地鼠式的调试。每一个不解决根本原因的修复都会使下一个bug更难找到。找到根本原因，然后修复它。

---

## 阶段1：根本原因调查

在形成任何假设之前收集上下文。

1. **收集症状：** 阅读错误消息、堆栈跟踪和重现步骤。如果用户没有提供足够的上下文，一次问一个问题。不要同时问五个问题。

2. **阅读代码：** 从症状追溯代码路径到潜在原因。搜索所有引用，阅读故障点周围的逻辑。

3. **检查最近的更改：**
   ```bash
   git log --oneline -20 -- <受影响的文件>
   ```
   之前是否工作正常？发生了什么变化？回归意味着根本原因在差异中。

4. **重现：** 你能确定地触发bug吗？如果不能，在继续之前收集更多证据。

5. **检查内存** 中同一区域的先前调试会话。同一文件中反复出现的bug是架构问题。

输出：**"根本原因假设：..."** ... 关于什么出错以及为什么出错的具体、可测试的声明。

---

## 阶段2：模式分析

检查此bug是否匹配已知模式：

**竞态条件** ... 间歇性、时间依赖性。查看对共享状态的并发访问。

**Nil/null传播** ... NoMethodError、TypeError。可选值缺少保护。

**状态损坏** ... 数据不一致、部分更新。检查事务、回调、钩子。

**集成失败** ... 超时、意外响应。外部API调用、服务边界。

**配置漂移** ... 在本地工作，在暂存/生产环境失败。环境变量、功能标志、数据库状态。

**缓存过期** ... 显示旧数据，清除缓存后修复。Redis、CDN、浏览器缓存。

还要检查：
- 项目中已知的相关问题
- Git日志中同一区域的先前修复。同一文件中反复出现的bug是架构问题，不是巧合。

**外部搜索：** 如果bug不匹配已知模式，在线搜索错误类型。**先清理：** 删除主机名、IP、文件路径、SQL、客户数据。搜索错误类别，而不是原始消息。

---

## 阶段3：假设测试

在编写任何修复之前，验证你的假设。

1. **确认假设：** 在可疑的根本原因处添加临时日志语句、断言或调试输出。运行重现。证据匹配吗？

2. **如果假设错误：** 搜索错误（先清理敏感数据）。返回阶段1。收集更多证据。不要猜测。

3. **三振规则：** 如果3个假设失败，**停止**。告诉用户：

   "测试了3个假设，都不匹配。这可能是架构问题而非简单bug。"

   选项：
   - 用新假设继续调查（描述它）
   - 升级供人类审查（需要了解系统的人）
   - 添加日志并等待（检测该区域，下次捕获）

**危险信号** ... 如果看到任何这些，放慢速度：
- "现在快速修复" ... 没有"现在"。正确修复或升级。
- 在追踪数据流之前提出修复方案 ... 你在猜测。
- 每次修复在其他地方揭示新问题 ... 错误的层，不是错误的代码。

---

## 阶段4：实施

一旦确认根本原因：

1. **修复根本原因，而不是症状。** 消除实际问题的最小更改。

2. **最小差异：** 触及最少的文件，更改最少的行数。抵制重构相邻代码的冲动。

3. **编写回归测试**，使其：
   - **失败** 没有修复（证明测试有意义）
   - **通过** 有修复（证明修复有效）

4. **运行完整测试套件。** 不允许回归。

5. **如果修复涉及>5个文件：** 在继续之前向用户标记影响范围。对于bug修复来说太大了。

---

## 阶段5：验证与报告

**全新验证：** 重现原始bug场景并确认已修复。这不是可选的。

运行测试套件。

输出结构化调试报告：

**调试报告**
- **症状：** 用户观察到的内容
- **根本原因：** 实际出了什么问题
- **修复：** 更改了什么，包含文件引用
- **证据：** 测试输出、显示修复有效的重现
- **回归测试：** 新测试的位置
- **相关：** 同一区域的先前bug、架构说明
- **状态：** 完成 | 有顾虑完成 | 阻塞

将报告保存到`memory/`，包含今天的日期，以便未来会话可以参考。

---

## 重要规则

- **3次以上修复尝试失败：停止并质疑架构。** 错误的架构，不是失败的假设。
- **绝不应用无法验证的修复。** 如果无法重现和确认，不要发布。
- **永远不要说"这应该能修复它。"** 验证并证明。运行测试。
- **如果修复涉及>5个文件：** 在继续之前向用户标记。
- **完成状态：**
  - 完成 ... 找到根本原因，应用修复，编写回归测试，所有测试通过
  - 有顾虑完成 ... 已修复但无法完全验证（例如间歇性bug，需要暂存环境）
  - 阻塞 ... 调查后根本原因不明，已升级
