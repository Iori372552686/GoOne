## 审查检查清单

**代码质量：**
- 关注点分离清晰？
- 错误处理恰当？
- 类型安全（如适用）？
- 遵循DRY原则？
- 边缘情况已处理？

**架构：**
- 设计决策合理？
- 考虑可扩展性？
- 性能影响？
- 安全隐患？

**测试：**
- 测试实际测试逻辑（而非模拟）？
- 覆盖边缘情况？
- 需要集成测试的地方有集成测试？
- 所有测试通过？

**需求：**
- 所有计划需求已满足？
- 实现符合规范？
- 无范围蔓延？
- 破坏性变更已记录？

**生产就绪性：**
- 迁移策略（如有架构更改）？
- 考虑向后兼容性？
- 文档完整？
- 无明显bug？

## 关键规则

**DO：**
- 按实际严重程度分类（并非所有都是Critical）
- 具体说明（文件:行，而非模糊）
- 解释问题为何重要
- 认可优点
- 给出明确结论

**DON'T：**
- 不检查就说"看起来不错"
- 将细微问题标记为Critical
- 对未审查的代码给出反馈
- 模糊表述（"改进错误处理"）
- 避免给出明确结论
