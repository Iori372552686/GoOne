# 无状态微服务功能模块的测验规范

> 适用范围：connsvr、roomcentersvr、infosvr、mysqlsvr 等采用 Service-Component 模式的无状态服务
> 参考实现：`src/roomcentersvr/logic/`（或对应服务的 logic/ 目录）

---

## 一、概述

无状态服务的功能模块以 Service-Component 模式运行，不维护玩家在线状态和数据缓存。核心在于路由解耦和事件解耦。测验核心目标：验证组件路由注册、并发安全、事件总线设计、数据读写正确性。

> GoOne 并发模型说明：无状态服务通过 `lib/service/transaction`（TransactionMgr）的**分片串行 key** 调度处理请求。即使无状态，同一业务 key（如房间 ID、排行榜 ID）的事务仍串行；跨 key 才并发。测验时重点验证"共享数据并发保护"与"无进程内玩家缓存"。

---

## 二、测验维度

### 维度 1：Service 容器与组件架构

| 检查点 | 目标 | 方法 |
|--------|------|------|
| **组件分类** | 基础设施/核心/扩展组件划分与设计一致 | 对比设计与实现：ServiceActor 结构体中的字段与 RegisterComponent |
| **初始化顺序** | 基础设施 → 核心业务 → 扩展 | 验证 OnInit 调用链 |
| **就绪状态** | 所有组件 OnInit 完成后才接收请求 | 验证就绪前请求是否被拒绝或 pending |

**发现的 BUG 类型**：组件未初始化就接收请求、组件分类混乱（基础设施混在扩展中）

### 维度 2：路由注册与分发

| 检查点 | 目标 | 方法 |
|--------|------|------|
| **cmd 唯一性** | 同一 cmd（uint32 主子命令组合）未被多组件注册 | 遍历所有组件注册表，检测冲突 |
| **注册方式合规** | 组件通过 ServiceActor.RegisterHandler 注册 | 检查是否直接操作框架 Router |
| **一级分发** | 核心分发逻辑中无 switch-case 按 CMD 分发 | 验证分发代码是简单的 cmd→component 映射 |
| **未知 CMD 处理** | 收到未注册的 CMD 时有降级行为 | 发送未注册的 CMD，验证有日志/错误响应 |

**发现的 BUG 类型**：路由冲突、核心分发中存在硬编码 switch-case 阻碍组件化、未知 CMD 无处理导致 crash

### 维度 3：并发安全

| 检查点 | 目标 | 方法 |
|--------|------|------|
| **共享数据保护** | 组件间共享数据有并发保护 | 检查 sync.RWMutex / atomic.Value / channel 的使用 |
| **无进程内玩家缓存** | 禁止在无状态服务中缓存玩家数据到进程内存 | 审查是否存在玩家维度的全局 map |
| **DB 原子操作** | 涉及计数/货币的操作使用原子操作 | 验证使用了 DB 的原子性操作（如 MySQL/xorm 的自增列更新、行锁、事务） |
| **EventBus 线程安全** | 并发发布/订阅时不会有数据竞争 | 检查 EventBus 实现是否有锁保护 |

**发现的 BUG 类型**：共享 map 无锁并发读写、无状态服务中缓存玩家数据、DB 非原子操作导致超卖、EventBus panic

### 维度 4：事件总线设计

| 检查点 | 目标 | 方法 |
|--------|------|------|
| **线程安全** | 并发 Publish 不会导致数据竞争 | 多 goroutine 同时 Publish，验证无 panic |
| **订阅/退订配对** | 组件 OnDestroy 时退订所有事件 | 对比 Subscribe 和 Unsubscribe 调用 |
| **禁止阻塞回调** | 事件回调中无阻塞操作 | 审查事件处理函数中是否包含 IO 等待或锁竞争 |
| **事件类型常量** | 事件类型在统一文件中定义，非硬编码 | 检查事件字符串是否在常量文件中有定义 |

**发现的 BUG 类型**：EventBus 无并发保护、事件回调中做 DB 操作阻塞发布者、事件类型字符串硬编码

### 维度 5：数据读写

| 检查点 | 目标 | 方法 |
|--------|------|------|
| **读写路径正确** | 每次请求独立读写 DB，不依赖前一次状态 | 验证 Handler 每次入口都重新读取数据 |
| **Key 格式正确** | KV Key 格式符合规范 | 验证 Key 模板 `{模块}:{ID}:{子项}` |
| **Redis 缓存一致性** | 缓存读写策略与设计一致 | 验证 Cache-Aside / Write-Through 策略的实现是否正确 |
| **跨服务调用** | 使用 lib/service/ssrpc 或 bus 异步投递，而非绕过框架 | 检查跨服务调用方式 |

**发现的 BUG 类型**：Key 格式不一致导致数据覆盖、缓存未设置 TTL 导致内存膨胀、跨服务调用绕过 ssrpc/bus 直接持有对端句柄

### 维度 6：组件生命周期

| 检查点 | 目标 | 方法 |
|--------|------|------|
| **OnInit** | 注册路由、订阅事件、初始化资源 | 验证 OnInit 中完成了必需操作 |
| **OnStart** | 注册定时任务、预热资源 | 验证 OnStart 在就绪后才执行 |
| **OnDestroy** | 退订事件、取消定时器、释放资源 | 验证 OnDestroy 清理完整 |

**发现的 BUG 类型**：OnStart 中访问未就绪的组件、OnDestroy 未清理导致 goroutine 泄漏、定时器未取消导致重复触发

## 三、与有状态服务的差异点

| 关注点 | 有状态（Actor-Component） | 无状态（Service-Component） | 测验差异 |
|--------|--------------------------|---------------------------|---------|
| 玩家缓存 | 进程内存缓存 | ❌ 禁止 | 无状态服务重点检查**无玩家缓存** |
| 数据读写 | 内存→定时回写 | 每次请求直接读写 DB | 无状态重点检查**读写路径一致性** |
| 并发模型 | TransactionMgr 按 key 分片串行 | TransactionMgr 按 key 分片串行；跨 key 并发 | 无状态重点检查**共享数据并发保护** |
| 生命周期 | 7 阶段（Init/Load/Online/Offline/Save/Destroy/Reset） | 3 阶段（Init/Start/Destroy） | 有状态重点检查**中间态** |
| Save | 组件 Save → 整文档 saveAll | 不适用 | 无状态服务不需要 Save |
| 路由 | 在 mainsvr/app.go 预注册 | 默认路由 | 无状态检查**未知 CMD 降级** |

## 四、优先检查清单

按以下优先级执行测验（P0 必须在报告前完成）：

- [ ] P0: 共享数据并发保护（数据竞争检测）
- [ ] P0: 无进程内玩家缓存
- [ ] P0: cmd 路由无冲突
- [ ] P0: DB 读写路径正确（每次请求独立读取）
- [ ] P1: EventBus 线程安全
- [ ] P1: 未知 CMD 降级处理
- [ ] P1: 订阅/退订配对
- [ ] P1: Redis 缓存策略正确（TTL、一致性）
- [ ] P2: Key 格式规范
- [ ] P2: 跨服务调用走 ssrpc/bus
- [ ] P2: 组件生命周期顺序
